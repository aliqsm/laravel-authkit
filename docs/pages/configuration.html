فایل تنظیمات

تنظیمات AuthKit در فایل زیر قرار دارند: 

config/authkit.php

اگر هنوز این فایل را در پروژه خود ندارید، ابتدا آن را منتشر کنید: 

php artisan vendor:publish --tag=authkit-config

حالت اجرا

با استفاده از گزینه app_mode می‌توانید حالت اجرای AuthKit را مشخص کنید: 

'app_mode' => 'web',
  • web: فعال‌سازی Routeهای مربوط به احراز هویت وب.
  • api: فعال‌سازی Routeهای مربوط به API.
  • null: غیرفعال‌کردن Routeهای AuthKit.

با تغییر این گزینه، می‌توانید مشخص کنید کدام بخش از Routeهای پکیج در پروژه بارگذاری شود.

تنظیم آدرس‌های انتقال در حالت API

اگر حالت اجرای AuthKit را روی api قرار داده‌اید، باید آدرس مقصد هر یک از مراحل زیر را در بخش api_urls مشخص کنید: 

'api_urls' => [
    'oauth_success' => env('AUTHKIT_URL_OAUTH_SUCCESS'),
    'oauth_failure' => env('AUTHKIT_URL_OAUTH_FAILURE'),
    'two_factor_challenge' => env('AUTHKIT_URL_TWO_FACTOR_CHALLENGE'),
    'password_reset' => env('AUTHKIT_URL_PASSWORD_RESET'),
    'email_verification' => env('AUTHKIT_URL_EMAIL_VERIFICATION'),
],

آدرس‌ها از طریق متغیرهای محیطی در فایل .env تنظیم می‌شوند و مشخص می‌کنند کاربر پس از هر یک از این مراحل به کدام صفحه در Frontend منتقل شود.

مدیریت قابلیت‌ها

در بخش features می‌توانید هر یک از قابلیت‌های اختیاری AuthKit را متناسب با نیاز پروژه فعال یا غیرفعال کنید: 

'features' => [
    'registration' => true,
    'google_login' => true,
    'two_factor_authentication' => true,
    'update_profile_information' => true,
    'change_password' => true,
    'security_activities' => true,
    'password_reset' => true,
],

برای فعال‌بودن هر قابلیت مقدار true و برای غیرفعال‌کردن آن مقدار false را قرار دهید.

تنظیمات احراز هویت دومرحله‌ای

در بخش two_factor می‌توانید تنظیمات مربوط به احراز هویت دومرحله‌ای را مطابق نیاز پروژه خود تغییر دهید: 

'two_factor' => [
    'challenge_expire_minutes' => (int) env('TWO_FACTOR_CHALLENGE_EXPIRE_MINUTES', 10),
    'setup_expire_minutes' => (int) env('TWO_FACTOR_SETUP_EXPIRE_MINUTES', 10),
    'recovery_code_length' => (int) env('TWO_FACTOR_RECOVERY_CODE_LENGTH', 12),
    'recovery_codes_count' => (int) env('TWO_FACTOR_RECOVERY_CODES_COUNT', 6),
],
  • challenge_expire_minutes: مدت اعتبار مرحله تأیید دومرحله‌ای.
  • setup_expire_minutes: مدت اعتبار فرایند فعال‌سازی.
  • recovery_code_length: طول هر کد بازیابی.
  • recovery_codes_count: تعداد کدهای بازیابی.

محدودسازی درخواست‌ها (Rate Limiting)

در بخش rate_limits می‌توانید تعداد درخواست‌های مجاز و مدت زمان محدودیت را برای بخش‌های مختلف AuthKit مشخص کنید. محدودیت‌ها بر اساس IP، ایمیل یا کاربر اعمال می‌شوند: 

'rate_limits' => [
    'authkit_pages' => [
        'ip' => ['max_attempts' => 120, 'decay_minutes' => 30],
    ],

    'authkit_login' => [
        'ip' => ['max_attempts' => 60, 'decay_minutes' => 30],
        'email' => ['max_attempts' => 10, 'decay_minutes' => 30],
    ],

    'authkit_logout' => [
        'ip' => ['max_attempts' => 30, 'decay_minutes' => 30],
        'user' => ['max_attempts' => 15, 'decay_minutes' => 30],
    ],

    // سایر محدودیت‌ها ...
],

مقدار max_attempts تعداد درخواست‌های مجاز و decay_minutes مدت زمان محدودیت را بر حسب دقیقه مشخص می‌کند. می‌توانید مقادیر هر بخش را متناسب با نیاز پروژه خود تغییر دهید.

تنظیمات صف (Queue)

AuthKit برای پردازش ایمیل‌ها و اعلان‌های امنیتی از سیستم صف (Queue) لاراول استفاده می‌کند. نوع اتصال صف از طریق متغیر QUEUE_CONNECTION در فایل .env مشخص می‌شود: 

QUEUE_CONNECTION=database

لاراول از اتصال‌های مختلفی مانند database، redis و sync پشتیبانی می‌کند. تنظیمات هر اتصال در فایل config/queue.php قرار دارد و می‌توانید آن‌ها را متناسب با زیرساخت پروژه خود تغییر دهید.

برای پردازش کارهای صف، باید یک Queue Worker فعال باشد. جزئیات ایجاد جدول صف و اجرای Worker در بخش نصب و راه‌اندازی توضیح داده شده است.

سفارشی‌سازی فایل‌ها

فایل‌های View و Assetهای AuthKit به‌صورت پیش‌فرض داخل پکیج باقی می‌مانند و برای استفاده معمول نیازی به انتشار آن‌ها ندارید. اگر قصد تغییر یا شخصی‌سازی این فایل‌ها را دارید، می‌توانید آن‌ها را به پروژه خود منتقل کنید.

انتشار Viewها

برای دریافت فایل‌های Blade و اعمال تغییرات دلخواه در صفحات AuthKit، دستور زیر را اجرا کنید: 

php artisan vendor:publish --tag=authkit-views
انتشار Assetها

برای دریافت فایل‌های CSS و JavaScript و شخصی‌سازی ظاهر یا رفتار صفحات، از دستور زیر استفاده کنید: 

php artisan vendor:publish --tag=authkit-assets

تنظیمات فونت

AuthKit از فونت دلخواه پروژه برای نمایش صفحات در حالت Web و قالب ایمیل‌ها در هر دو حالت Web و API استفاده می‌کند. برای تنظیم فونت، خانواده فونت، فونت‌های جایگزین و مسیر فایل‌های فونت با وزن‌های مختلف را در بخش font مشخص کنید: 

'font' => [
    'family' => 'ExampleFont',
    'fallback' => 'Tahoma, Arial, sans-serif',
    'weights' => [
        400 => 'fonts/example-font/ExampleFont-Regular.woff2',
        500 => 'fonts/example-font/ExampleFont-Medium.woff2',
        700 => 'fonts/example-font/ExampleFont-Bold.woff2',
    ],
],

فایل‌های فونت باید در مسیرهای مشخص‌شده در پروژه قرار داشته باشند. نام فونت، فونت‌های جایگزین و وزن‌های موردنیاز را متناسب با فونت مورد استفاده خود تنظیم کنید.
